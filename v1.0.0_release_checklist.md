# v1.0.0 Release Checklist

This checklist tracks the minimum stabilization work required before cutting `v1.0.0`.

## Current Recommendation

- Recommended current release posture: `v0.x`
- GA candidate mode today: `monolith`
- `distributed` is now explicitly scoped as `experimental` for the first `v1.0.0` stable release

## 1. Version And Docs Alignment

- [x] Update the public version story so `README.md`, architecture docs, release notes, and config examples all describe the same effective runtime model.
- [x] Publish a clear feature matrix that marks each capability as `GA`, `experimental`, or `planned`.
- [x] Confirm that every shipped migration, config field, and startup command in docs matches the current code path.
- [x] Reconcile `v4.3` / `v4.4` design references so users can tell which document set matches the shipping implementation.

Acceptance:

- No public-facing doc claims a mode, method, or config field that is not present in the current branch.
- Users can follow `README.md` from an empty environment to a successful smoke test without missing undocumented steps.

## 2. Default CI Gate

- [x] Add one repository-wide GitHub Actions workflow that runs `go test ./... -count=1`.
- [ ] Ensure required branch protection uses the general CI workflow, not just the targeted migration/integration jobs.
- [x] Add an explicit release-tag verification run that includes the same general CI workflow plus targeted integration workflows.

Manual repository setting still required:

- Require the `go-test` job from [`.github/workflows/ci.yml`](/Users/stellajen/Documents/workspace/mcp_for_appium/.github/workflows/ci.yml) on the protected release branch before merge.

Acceptance:

- Every pull request and release tag is blocked on the general Go test suite.
- Release branches cannot merge or tag green builds without the same baseline test gate.

## 3. Security Defaults Tightening

- [x] Change production-facing examples and deployment docs to default external HTTP/WS to TLS-enabled operation.
- [x] Change internal RPC examples and recommended deployment defaults to `tls` instead of `insecure`.
- [x] Add `SECURITY.md` with reporting instructions, supported versions, and a short description of auth/TLS expectations.
- [x] Review every public-facing example for long-lived credentials, localhost-only assumptions, or insecure transport defaults.

Acceptance:

- Production docs no longer recommend plaintext external traffic.
- Internal RPC examples no longer normalize insecure transport as the default production posture.

## 4. GA Scope Declaration

- [x] Decide whether `distributed` is part of `v1.0.0` GA or remains experimental for the first stable release.
- [x] Land distributed result callbacks, ownership leases, worker recovery handling, and stale-result protection.
- [x] Add one distributed end-to-end integration flow that exercises accepted worker execution through final callback closure.
- [x] Add tenant or ownership validation for WebSocket trace subscriptions before calling that surface GA.
- [x] Add one artifact-inclusive integration path so screenshots and artifact metadata are covered by automated tests.

Acceptance:

- Every GA-marked mode has an end-to-end automated path and a clearly documented support boundary.
- Any remaining experimental surface is explicitly labeled in docs and release notes.

## 5. Release Notes And Changelog

- [x] Add `CHANGELOG.md`.
- [x] Draft the `v1.0.0` release notes with breaking changes, deployment steps, migrations, and known limitations.
- [x] Record upgrade notes for operators coming from pre-`v1.0.0` branches, including new migrations and config fields such as `worker.advertise_addr`.
- [x] Include a short rollback section covering schema, config, and deployment rollback expectations.

Acceptance:

- A release manager can cut `v1.0.0` from committed documentation without reconstructing migration, config, or known-risk notes from chat history.

## Suggested Exit Criteria

- `monolith` is explicitly declared GA with matching docs and automated coverage.
- General CI is enforced on pull requests and release tags.
- Production docs default to secure transport.
- The release notes clearly state whether `distributed` is GA or still experimental.
- The changelog and release notes cover new migrations, auth changes, worker advertise address behavior, and distributed lease semantics.
